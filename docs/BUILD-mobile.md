# Building the waiter app

Flutter, one codebase, both stores. Built in Android Studio as you prefer.

```bash
cd mobile
flutter pub get
flutter build appbundle --release        # Android → Play Console
flutter build apk --release              # or a direct APK for your own customers
```

iOS goes through Codemagic exactly like your other apps (`flutter build ipa`).

## Before the first build

`mobile/` holds the app source plus the two platform files that actually matter;
the rest of the Android/iOS scaffolding is generated by Flutter:

```bash
cd mobile
flutter create . --project-name noktapp_garson --org com.noktapp --platforms android,ios
```

Then re-apply the two files this package ships, because `flutter create`
overwrites them:

* `android/app/src/main/AndroidManifest.xml` — internet, Wi-Fi state, multicast,
  and the network security config that allows plain HTTP **only** to private IP
  ranges (the till). Everything leaving the building stays HTTPS.
* `ios/Runner/Info.plist.additions` — paste these keys into `Info.plist`.
  Without `NSLocalNetworkUsageDescription` and `NSBonjourServices`, iOS 14+
  silently blocks discovery and the app never finds the till.

## What the app does — and deliberately does not

Does: take orders, send them to the kitchen and bar, show the bill, print the
bill on the till's printer, mail the bill to the guest.

Does not: take payments, open the drawer, run reports, change prices. Money is
handled at the till, which is what the restaurant's accountant expects and what
keeps the phone a low-risk device to lose.

## How it finds the till

1. Bonjour/mDNS lookup for `_noktapp-pos._tcp` — instant on a normal router.
2. If multicast is filtered, it sweeps the phone's own /24 and asks every
   address `GET /api/mobile/ping`. About a second.
3. The address it found is remembered, and re-checked on every launch.
4. If neither works — the waiter is outside, or on the guest network — the same
   request goes to `pos.noktapp.com/api/mobile/relay.php`, which holds it until
   the restaurant PC picks it up. The app shows an orange bar so the waiter
   knows why things are a beat slower.

## Offline

An order typed with no connection at all is stored on the phone and replayed
when the till is reachable. Every queued operation carries a UUID, and the till
remembers it, so a replay can never duplicate an order. The home screen shows
"N bekliyor" while anything is queued.

## Pairing a phone

On the till: **Ayarlar → Telefonlar → Yeni cihaz bağla** shows a six-digit code
valid for ten minutes. On the phone: enter the code plus the waiter's username
and password. The phone gets a 30-day token, refreshed as it is used. Revoke a
lost phone from the same screen.
